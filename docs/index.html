MessengerApp API

API для мессенджера реального времени. Для защищённых запросов используется JWT-токен, полученный через endpoint входа. Обмен сообщениями в реальном времени осуществляется через SignalR-хаб.

Базовые URL:
Локальная разработка: http://localhost/api
Продакшн: https://yourdomain.com/api

Быстрый старт

Зарегистрируйте пользователя, получите токен и выполните первый защищённый запрос.

1. Регистрация

curl -X POST "http://localhost/api/auth/register" \
  -H "Content-Type: application/json" \
  -d '{
    "login": "ivan.petrov",
    "password": "strong-password",
    "email": "ivan@example.com",
    "nickname": "Ivan"
  }'

Ответ:

{ "message": "Операция выполнена успешно" }

2. Получение JWT-токена

curl -X POST "http://localhost/api/auth/login" \
  -H "Content-Type: application/json" \
  -d '{
    "loginOrEmail": "ivan.petrov",
    "password": "strong-password"
  }'

Ответ:

{ "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..." }

3. Защищённый запрос

curl -X GET "http://localhost/api/users/search?query=Iv" \
  -H "Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."

Ответ:

[
  { "id": "7f9f0f3d-4f7e-4b2d-9a0f-21a8f8d7c111", "nickname": "Ivan" }
]

Аутентификация

Все защищённые endpoints требуют заголовок Authorization: Bearer <token>. Исключения: регистрация и вход.

Auth

POST /auth/register

Создаёт учётную запись. Пароль хэшируется на сервере.

Тело запроса

POST /auth/login

Возвращает JWT-токен.

Users

GET /users/search?query={query}

Поиск пользователей по никнейму (мин. 2 символа).

Ответ: массив объектов { id, nickname }

PUT /users/profile

Обновление никнейма текущего пользователя. Тело: { "nickname": "Новый ник" }

Messages

GET /messages/contacts

Список собеседников с последним сообщением.

GET /messages/conversation/{otherUserId}

История сообщений. Параметры: skip, take.

POST /messages/upload?type=image|voice

Загрузка файла. Ответ: { "url": "/uploads/..." }

Realtime через SignalR

Хаб доступен по адресу: wss://<сервер>/hubs/chat. Аутентификация через access_token в query-строке.

Методы хаба

SendMessage

Параметры: recipientId (string), text (string|null), repliedToMessageId (string|null), attachments (Attachment[]|null).

События хаба

СобытиеОписаниеПараметр
ReceiveMessageНовое входящее сообщениеMessage
MessageSentПодтверждение отправкиMessage
NewContactПоявился новый контакт (первое сообщение)Contact
ErrorОшибка обработки{ message }

Примеры подключения

const connection = new signalR.HubConnectionBuilder()
  .withUrl("/hubs/chat", { accessTokenFactory: () => token })
  .withAutomaticReconnect()
  .build();

connection.on("ReceiveMessage", msg => console.log(msg));
connection.on("MessageSent", msg => console.log(msg));
connection.on("NewContact", contact => console.log(contact));
connection.start();

await connection.invoke("SendMessage", recipientId, "Hello", null, null);
var connection = new HubConnectionBuilder()
  .WithUrl("https://server/hubs/chat", options => {
      options.AccessTokenProvider = () => Task.FromResult(token);
  })
  .Build();

connection.On<MessageDto>("ReceiveMessage", msg => {});
connection.On<MessageDto>("MessageSent", msg => {});
await connection.StartAsync();

await connection.InvokeAsync("SendMessage", recipientId, "Hello", null, null);

Жизненный цикл сообщения

  1. Клиент вызывает SendMessage.
  2. Сервер отправляет отправителю MessageSent.
  3. Если получатель онлайн — ему ReceiveMessage, статус Delivered.
  4. Если офлайн — сообщение сохраняется со статусом Sent.

Документация сгенерирована из OpenAPI-спецификации и описания SignalR-хаба. Актуальная версия всегда доступна в репозитории проекта.
